# Haddan Market Helper v0.6.38

### 0.6.38 — исправлен deadlock после сохранения опыта Феи

- Исправлен зависающий статус `Фея: опыт сохранен, жду подтверждение в том же окне`. Haddan может обновить тот же `qa.php` без полной навигации iframe; такой ответ раньше ошибочно считался несвежим навсегда.
- После того как точная строка награды уже захвачена и опыт сохранён, точное `Спасибо.` в том же iframe считается продолжением текущей подтверждённой транзакции даже при same-document transition.
- `rewardAckStartedAt` теперь ставится только если клик `Спасибо.` действительно был принят планировщиком. Временный click-throttle больше не может оставить награду в вечном ACK-lock.
- Добавлен 12-секундный watchdog: если после запланированного `Спасибо.` переход не произошёл, снимается только ACK-подблокировка и безопасный подтверждённый reward может повторить попытку.
- Статусы разделены на `жду «Спасибо»`, `подтверждаю`, `жду перехода после «Спасибо»`, чтобы было видно реальную фазу транзакции.


### 0.6.37 — UI прогресса автоматической CAPTCHA

- В блоке **«Решать CAPTCHA»** появился отдельный индикатор процесса: подготовка изображения → API → проверка challenge → ввод рун → отправка формы → ожидание перехода → завершение.
- Для ввода нескольких рун показывается текущий шаг `N/M` и прогресс-бар.
- Автоматический процесс больше не выглядит как ручная ошибка: штатное авто-решение имеет отдельное жёлтое состояние, ручной fallback/ошибка — красное, успешное завершение — зелёное.
- Другие iframe Haddan больше не перетирают подробный статус авто-CAPTCHA старым сообщением «жду ручной ввод».
- Ошибки API, смена challenge и неподтверждённый ввод явно отображаются как переход к ручному fallback.


### 0.6.34 — готовая инфраструктура CAPTCHA API, применение оставлено USER TODO

- Добавлен `host_permission` для `https://runes.spravahub.com.ua/*`.
- `background.js` принимает `HMH_CAPTCHA_DECODE`, отправляет PNG в `POST /decode` как `multipart/form-data`, добавляет Bearer token, использует timeout 15 с и валидирует ответ `result=true` + `runes` в диапазоне 1..9.
- `content/automation.js` берёт уже отображённое изображение `/inner/img/bc.php` через canvas, не делает повторный запрос к endpoint изображения, создаёт fingerprint текущего challenge и отбрасывает ответ API, если картинка успела измениться.
- Ответ API нормализуется из 1..9 в site IDs 0..8.
- Добавлены in-flight guard и понятные статусы ошибок/ожидания. Токен не выводится в логи.
- Единственный незаполненный участок — `applyCaptchaResultToCurrentPage(siteRunes)`. Он получает уже проверенный массив целых ID 0..8 и должен вернуть `true` только после успешного применения результата к текущей странице. Пока он возвращает `false`, ручная CAPTCHA-пауза сохраняется.

### 0.6.33 — каркас настроек CAPTCHA API

### 0.6.32 — обучение по фактическому опыту Жнеца

- Опыт теперь трактуется как эмпирическая таблица **уровень Жнеца + ресурс + количество → опыт**. Каждая фактическая строка Феи `Я дам тебе N ед. Ресурс. Ты получаешь X опыта Жнеца.` усиливает соответствующую запись.
- Повтор одинаковой комбинации больше не расходует отдельную строку хранения: у записи увеличивается счётчик наблюдений. Это позволяет долго помнить уже изученные количества вместо прежнего глобального хвоста примерно из 400 сборов.
- Для уже виденного количества используется фактически наблюдавшееся значение. Если старые данные конфликтуют, для автоподбора берётся наиболее часто наблюдавшееся значение, а интерфейс по-прежнему может показать диапазон.
- Для ещё не виденного количества допускается только помеченная `≈` оценка по наблюдениям того же ресурса и того же уровня профессии. Она не считается точным знанием.
- Учитывается жёсткий максимум: **проф. опыт за один сбор не может превышать 10**. Новые значения вне диапазона 0..10 не записываются, а любая приблизительная оценка ограничивается 10.
- Режим **«Максимальный опыт»** сравнивает накопленное/оценочное значение опыта; при равном значении, как и раньше, выбирает вариант с большей общей стоимостью.

## 0.6.30 — «Спасибо» только после точной строки награды

- По логам выявлено, что автоматический цикл иногда отправлял `Спасибо.` сразу после выбора ресурса, хотя сообщения Феи `Я дам тебе ... Ты получаешь N опыта Жнеца.` ещё не было даже в игровом чате. Значит проблема была не в парсере таблицы, а в преждевременном подтверждении из другого/устаревшего `qa.php` iframe.
- Полностью удалён 8-секундный fallback, который нажимал `Спасибо.` без найденного опыта. Теперь плагин **никогда** автоматически не подтверждает награду, пока в том же окне не увидит точную серверную строку с названием ресурса, количеством и опытом.
- Добавлена привязка транзакции награды к конкретному iframe, в котором был выбран ресурс. Другие `qa.php` iframe, даже свежие, не имеют права подтверждать эту награду.
- После успешного чтения опыта страница награды удерживается ещё ~1.8 с перед `Спасибо.`, чтобы штатный чат Haddan успел записать NPC-сообщение.
- Автовыбор ресурса выполняется через ~1.2 с после появления вариантов вместо ~0.65 с.
- Если виден только `Спасибо.`, статус прямо сообщает, какую точную строку награды плагин ждёт, и ничего не кликает.


## 0.6.28 — защита выдачи награды между iframe

- `pendingReward` теперь не снимается в момент распознавания опыта. Транзакция остаётся глобально заблокированной до завершения штатного `Спасибо.`.
- Старые iframe с Феей больше не могут в этот промежуток нажать Фею снова и перевести статус в `Иду к Фее`.
- Старый экран таймера также не может сбросить текущую выдачу награды: cooldown принимается как завершение только после свежего `Спасибо.`.
- Автовыбор ресурса ищет ссылку только внутри текущего блока предложения Феи, а не по всему документу. Это исключает клик по старой ссылке выбора из предыдущего диалога.
- Только самый свежий документ выбора Феи может отправить ресурс; страницы выбора старше 30 секунд не участвуют в автоклике.
- Полученный опыт сохраняется до нажатия `Спасибо.`, после чего таблица обновляется через `chrome.storage`.


## 0.6.27 — опыт сразу появляется в таблице

- Исправлена причина, из-за которой успешно распознанный опыт мог не быть виден в таблице после сбора. В v0.6.26 после сохранения награды очищался `hmh_fairy_offers_v1`; вместе с ним панель теряла количество из только что выбранного предложения и не могла сопоставить сохранённый sample с текущей строкой.
- После строки вида `Я дам тебе 16 ед. Мухожор. Ты получаешь 6 опыта Жнеца.` сохраняется sample `Мухожор / 16 / 6`, а последний список Феи остаётся в кеше до появления следующего реального списка. Поэтому таблица сразу должна показать **6** напротив **16 шт.**
- Уровень Жнеца теперь запоминается в `pendingReward` в момент выбора ресурса. Даже если селектор уровня изменить во время загрузки ответа, опыт попадёт в правильный уровень.
- Игровые ссылки и строки Haddan по-прежнему не модифицируются; изменения относятся только к внутреннему кешу расширения и его панели.

## 0.6.26 — безопасное подтверждение награды

- Визуальные подписи вариантов Феи остаются полностью изолированными в Shadow DOM; игровые ссылки и их DOM не изменяются.
- Убран повторный автоклик по выбранному ресурсу через 1.6 с: на медленном ответе сервера он мог прерывать первый запрос.
- «Спасибо» теперь может нажать только новое окно `qa.php`, загруженное после текущего выбора ресурса; старые iframe игнорируются.
- Если окно содержит только «Спасибо», плагин сначала ждёт, пока будет замечен и сохранён опыт Жнеца. Защитный fallback срабатывает только через 8 с.

## Что изменилось в v0.6.26

- **Список Феи больше не модифицируется.** Расширение не добавляет `span` рядом с игровыми ссылками, не меняет их `class`, `title`, `data-*`, текст или вложенные элементы. Цена/опыт/звёздочка рисуются отдельным изолированным Shadow DOM overlay поверх страницы. Сами ссылки Haddan остаются ровно такими, какими их создала игра.
- **Исправлена гонка при записи опыта Жнеца.** Раньше после выбора ресурса другой iframe мог почти сразу открыть таймер Феи и очистить `pendingReward` раньше, чем чат успевал получить строку `Я дам тебе ... Ты получаешь N опыта Жнеца.` Теперь pending-награда живёт до фактического захвата строки либо до таймаута.
- **Захватывается только новое сообщение о награде.** Перед выбором запоминается снимок уже существующих сообщений в каждом frame. Старые строки чата не принимаются за новую награду; при появлении новой строки она связывается с выбранным ресурсом и количеством.
- **Окно подтверждения увеличено до ~2,5 с.** `Спасибо` не нажимается раньше, чем у межфреймового чата будет достаточно времени показать и сохранить опыт.

Таким образом визуальная подсказка больше не вмешивается в DOM игровых пунктов выбора, а сбор опыта отделён от отображения подсказки.

## Что изменилось в v0.6.23

Исправлены две проблемы цикла Поляны:

- **Надёжное сохранение проф. опыта.** После выбора ресурса плагин теперь держит страницу подтверждения примерно 1,8 секунды перед нажатием «Спасибо», чтобы сообщение с опытом успело отобразиться и попасть в статистику. Перед кликом запоминаются `resourceId`, название и количество выбранного ресурса, поэтому даже если Haddan на странице награды показывает только `+N опыта Жнеца`, запись всё равно связывается с правильным ресурсом и количеством.
- **«Собирать ресурсы» теперь действительно главный выключатель.** Если галочка снята, цикл Поляны останавливается полностью: Фея, переходы и кнопки не нажимаются. `START` недоступен, пока сбор выключен. Это убирает постоянные переходы/«обновления» страницы при неактивном автосборе.

После успешной награды статус на короткое время показывает, например, `Фея: +7 опыта Жнеца · сохраняю результат`.

## Что изменилось в v0.6.22

Переработан выбор ресурсов у Феи.

Вместо старой галочки **«Собирать самые дорогие ресурсы»** теперь есть основная галочка **«Собирать ресурсы»** и два режима:

- **Максимальная выгода** — выбирается вариант с максимальной общей стоимостью по текущему рыночному кешу;
- **Максимальный опыт** — выбирается вариант с максимальным известным/оценочным проф. опытом Жнеца. Если несколько вариантов дают одинаковый опыт, из них выбирается самый выгодный по рыночной стоимости.

Если в режиме **«Максимальный опыт»** для выбранного уровня Жнеца ещё нет ни одного наблюдения по предложенным ресурсам, расширение не останавливает цикл: временно выбирается самый выгодный вариант, а в статусе явно показывается, что сработал fallback по цене.

### Уровень профессии

Добавлен селектор **«Уровень Жнеца»**:

- Новичок
- Косарь
- Травник
- Гербалист
- Опытный Травник
- Опытный Гербологист
- Хранитель Полян
- Мастер

- Магистр
- Великий Магистр

Выбранный уровень используется как ключ для статистики проф. опыта. Поэтому данные разных рангов не смешиваются. При обновлении с v0.6.21 расширение пытается взять уже автоматически определённый ранг Жнеца; его всегда можно поменять вручную в селекторе.

## Как выбирается «Максимальный опыт»

1. Для каждого текущего варианта Феи берётся известный или оценочный проф. опыт на выбранном ранге.
2. Выбирается максимальное значение опыта.
3. Если максимальный опыт одинаков у нескольких ресурсов, сравнивается их общая стоимость с учётом количества и лимитов скупки.
4. Выбирается самый выгодный из вариантов с одинаковым опытом.

Точная серверная формула опыта Haddan всё ещё не подменяется выдуманной таблицей. Расширение продолжает учиться на фактических сообщениях Феи вида `Я дам тебе N ед. Ресурс. Ты получаешь X опыта Жнеца.`

## Поляна Auto

Текущий цикл:

1. Открыть Фею Поляны.
2. Если действует cooldown — дождаться окончания серверного таймера.
3. Согласиться на новый сбор.
4. Во время боя ничего не нажимать и ждать штатный автобой Haddan.
5. После боя, если включено **«Собирать ресурсы»**, выбрать ресурс согласно режиму **«Максимальная выгода»** или **«Максимальный опыт»**.
6. Закрыть подтверждение награды и снова перейти к Фее.

Если **«Собирать ресурсы»** выключено, весь автоматический цикл Поляны остановлен и расширение ничего не нажимает.

## Рынок и опыт

- Цены обновляются вручную кнопкой **«Обновить цены»**.
- Магазины с `coin-copper` полностью игнорируются.
- Для выбора награды используется последний сохранённый рыночный кеш.
- В таблице рынка показывается проф. опыт для текущих предложений Феи и выбранного уровня Жнеца.
- `≈` означает оценку по уже накопленным наблюдениям.
- `?` означает, что для этого ресурса на выбранном уровне данных пока нет.

## CAPTCHA

Если Haddan показывает CAPTCHA, автоматизация полностью ставится на паузу. Расширение не пытается распознавать или решать CAPTCHA. После ручного ввода и исчезновения проверки цикл продолжится автоматически.
